¿Qué es un arreglo?

Antes de programar, necesitamos comprender la idea. Un arreglo es mucho más que una lista: es una estructura con reglas precisas sobre cómo se organiza la memoria.

Un arreglo es una colección finita, homogénea y ordenada de elementos del mismo tipo. Cada elemento ocupa una posición identificada por un índice que comienza en cero.
A = [ a₀ , a₁ , a₂ , ... , aₙ₋₁ ]  |  índice ∈ [0, N-1]
// SECCIÓN 02

Características esenciales

Todo arreglo cumple un contrato de diseño. Comprenderlo es el primer paso para usarlo correctamente y, después, para encapsularlo.

01
Homogeneidad
Todos los elementos son del mismo tipo de dato: `int[]`, `String[]`, `Estudiante[]`…
02
Orden
Los elementos están en una secuencia lineal. El índice define exactamente su posición.
03
Tamaño fijo
La longitud se fija al crear el arreglo. No se puede modificar después.
04
Acceso O(1)
El acceso por índice es constante gracias al cálculo directo de direcciones de memoria.
05
Memoria contigua
Los elementos se almacenan en bloque. Esto favorece la caché del procesador.
06
Índice base 0
El primer elemento vive en el índice `0`; el último en `N-1`. No hay índice `N`.

Las limitaciones del arreglo desnudo

Antes de encapsular, hay que reconocer los problemas del arreglo primitivo. Estas son las razones por las cuales la POO interviene.

Tamaño inmutable

Un arreglo de new int[10] jamás podrá contener 11 elementos. Para crecer hay que crear otro arreglo y copiar todo.

Acceso inseguro

Acceder a arr[10] en un arreglo de longitud 10 dispara ArrayIndexOutOfBoundsException.

Sin protección

El arreglo expone su tamaño y sus elementos a cualquiera. No hay invariantes que lo protejan.

Inserción costosa

Insertar o eliminar en medio de un arreglo obliga a desplazar N elementos. Costo O(N).

Desperdicio

Si se sobredimensiona "por si acaso", se reserva memoria que nunca se usa.

Sin semántica

Un int[] no sabe si representa notas, edades o precios. No hay dominio, no hay significado.

// SECCIÓN 06

La solución: encapsular en POO

La programación orientada a objetos no reemplaza a los arreglos: los envuelve. Al esconder el arreglo dentro de una clase, se controla cada acceso.

  • Encapsulamiento
    El arreglo pasa a ser private. Nadie lo toca sin pasar por los métodos.
  • Composición
    La clase tiene un arreglo como parte de su estado interno.
  • Responsabilidad única
    La clase gestiona la colección; el cliente solo llama a agregar() u obtener().
  • Interfaz controlada
    Se expone lo necesario. La implementación queda oculta y puede cambiarse sin romper a los clientes.

Código real, sin adornos

Este es el esqueleto clásico de una clase que encapsula un arreglo y ofrece una interfaz segura. Léelo despacio: cada línea tiene una razón de ser.

Coleccion.java
JAVA
public class Coleccion<T> {

    private T[] elementos;        // arreglo encapsulado
    private int cantidad;         // elementos realmente guardados
    private static final int INICIAL = 4;

    public Coleccion() {
        elementos = (T[]) new Object[INICIAL];
        cantidad  = 0;
    }

    public void agregar(T e) {
        if (cantidad == elementos.length) {
            redimensionar();
        }
        elementos[cantidad++] = e;
    }

    public T obtener(int i) {
        if (i < 0 || i >= cantidad) {
            throw new IndexOutOfBoundsException(
                "Índice fuera de rango: " + i);
        }
        return elementos[i];
    }

    public int tamaño() {
        return cantidad;
    }

    private void redimensionar() {
        T[] nuevo = (T[]) new Object[elementos.length * 2];
        System.arraycopy(elementos, 0, nuevo, 0, cantidad);
        elementos = nuevo;
    }
}
